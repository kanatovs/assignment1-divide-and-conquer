# Разбор проекта и подготовка к объяснению

Это пояснение к реализации в этой папке, а не дополнительное условие задания. Сам PDF не описывает длительность или формат отдельной защиты. Ниже — вопросы для подготовки, а не обещание, что преподаватель спросит именно их.

## 1. Что вообще делает проект

Есть четыре отдельных алгоритма. Два сортируют числа; третий находит число на заданной позиции в отсортированном порядке; четвёртый находит две ближайшие точки.

Divide-and-conquer означает «разделить → решить меньшие задачи → объединить или выбрать нужный результат». Рекурсия — вызов метода из него самого на меньшей задаче. Базовый случай останавливает деление.

Начни с `Main.java`: там маленькие понятные входы. Затем открой четыре алгоритма. `Experiment` отвечает за замеры, а не за саму сортировку. `ReportWriter` и `PlotWriter` оформляют результаты; их графический код необязательно изучать прежде основной логики.

## 2. MergeSort

Пример: `[8,3,6,1]` делится на `[8,3]` и `[6,1]`. После сортировки частей получаем `[3,8]` и `[1,6]`. При слиянии сравниваем первые ещё не использованные числа: 3 и 1, затем 3 и 6, затем 8 и 6. Получаем `[1,3,6,8]`.

Важно: в текущем коде четыре числа сразу попадут в insertion sort, потому что `CUTOFF=24`. Пример показывает общую идею MergeSort. Чтобы увидеть рекурсивное деление в отладчике, возьми больше 24 элементов.

`sort()` создаёт один `buffer`. `sortRange()` делит диапазон. `merge()` объединяет отсортированные части. `low/high` — включённые границы, `middle` — середина. `left/right` — указатели на ещё не использованные элементы двух половин. Сначала данные копируются в буфер, чтобы запись результата не затёрла ещё не прочитанные числа.

Почему `<=`, а не `<`? При равных значениях первым берётся элемент левой половины: сохраняется устойчивость.

Рекуррентность: `T(n)=2T(n/2)+Θ(n)`. Две половины плюс линейное слияние. На каждом уровне суммарно примерно n работы, уровней примерно log₂n, итого Θ(n log n). Память: O(n) для буфера, O(log n) для стека.

Коротко по-английски: “MergeSort splits the array into two halves and merges the sorted halves. I use one reusable buffer and insertion sort for ranges of at most 24 elements.”

## 3. QuickSort

Pivot — опорное значение. Например, при pivot=5 массив `[7,2,5,1,5,9]` разделится на значения меньше 5, равные 5 и больше 5. Порядок внутри этих зон пока не обязан быть отсортированным.

`ArraySupport.partition()` делает три зоны без отдельного массива. `less` — начало равной зоны, `current` — следующий неизвестный элемент, `greater` — последняя позиция неизвестной зоны.

Если элемент меньше pivot, меняем его с `less` и двигаем оба указателя. Если равен — двигаем `current`. Если больше — меняем с `greater` и уменьшаем `greater`, но **не увеличиваем current**: прилетевший справа элемент ещё не проверен.

В `QuickSorter.sortRange()` запомни главную часть: меньшая зона отправляется в новый рекурсивный вызов; для большей меняются `low/high` и продолжается `while`. Цикл не создаёт новый рекурсивный уровень.

Ожидаемое время O(n log n), худшее Θ(n²). Стек O(log n) благодаря smaller-first, даже если pivot оказался неудачным. Не говори, что smaller-first устраняет худшее квадратичное время: он ограничивает глубину стека.

Seed делает последовательность случайных pivot воспроизводимой. Pivot всё ещё выбирается генератором, а не фиксируется первым или последним элементом. Одинаковый seed помогает повторить эксперимент.

Коротко: “QuickSort uses a random pivot and a three-way in-place partition. I recurse on the smaller partition and process the larger one in a loop to keep the stack depth logarithmic.”

## 4. Deterministic Select

Это **не полноценная сортировка**. Для `[8,2,5,1,9]` отсортированный порядок `[1,2,5,8,9]`. `k=2` означает третье наименьшее число: ответ 5. Индексы начинаются с нуля. Вызов меняет порядок исходного массива, поэтому для сохранения исходника передают `.clone()`.

Сначала разделяем числа на группы максимум по пять. Каждую маленькую группу сортируем и берём её среднее по порядку значение. Это **медиана**, не среднее арифметическое. Например, медиана `[1,2,3,9,100]` равна 3.

Медианы групп переносим в начало того же диапазона. Рекурсивно выбираем медиану полученных медиан. Она становится pivot. После partition идём только в часть, где находится k; если k в равной зоне, ответ уже pivot.

Почему именно по пять? В анализе полная подходящая группа гарантирует три значения по нужную сторону от своей медианы. Получается отбрасывать примерно 30% элементов независимо от исходного порядка. Последняя неполная группа даёт только постоянную поправку.

Рекуррентность: `T(n)≤T(n/5)+T(7n/10+O(1))+O(n)`. Первая рекурсия выбирает pivot, вторая ищет ответ в нужной части. Доли 0.2 и 0.7 суммарно меньше единицы. По уровням дерево требует примерно `n+0.9n+0.9²n+...`, что даёт O(n), а верхний проход требует Ω(n), поэтому худшее время Θ(n).

Не применяй обычную Master Theorem как будто обе подзадачи одинаковые. Здесь подходит Akra–Bazzi или объяснение убывающей суммы. Медиана медиан не обязана совпадать с точной медианой всего массива; достаточно гарантированно неплохого разбиения.

Коротко: “Median-of-medians chooses a deterministic pivot using groups of five. It guarantees that a constant fraction of elements can be discarded, so selection has linear worst-case time.”

## 5. Closest Pair

`Point` — пара координат x и y. Ищем две точки с минимальным евклидовым расстоянием. Для (0,0) и (3,4) расстояние 5.

Сначала сортируем точки по x. Делим по индексу на две примерно равные части. Находим ближайшую пару слева и справа. Но лучший ответ может состоять из одной точки слева и одной справа!

Пусть d — меньшее из двух найденных расстояний. Возможную лучшую пересекающую пару ищем только в полосе около разделительной линии. Точки в полосе упорядочены по y: для каждой достаточно проверить ограниченное число следующих соседей, в этой реализации максимум семь.

Главный тонкий момент: при входе диапазон ещё отсортирован по x, при выходе — уже по y. Поэтому `middleX` сохраняется **до** вызовов рекурсии. Затем два y-отсортированных диапазона объединяются за O(n), а не сортируются заново.

`solveRange()` использует полуоткрытые границы `[low,high)`: high не входит. Это отличается от включённых границ у сортировок. Деление по индексу правильно работает даже при одинаковых x.

Меньше двух точек: пары нет, расстояние положительная бесконечность. Одинаковые точки: расстояние 0. `bruteForce()` перебирает все пары и нужен как эталон на маленьких данных.

Рекуррентность `2T(n/2)+Θ(n)`, итог Θ(n log n). Вспомогательная память O(n). Если заново сортировать полосу на каждом уровне, можно получить O(n log² n): линейное y-слияние здесь принципиально.

Коротко: “The algorithm solves the left and right halves and checks a narrow strip for a better crossing pair. It maintains y order with a linear merge, which keeps the total time O(n log n).”

## 6. Метрики и эксперименты

`time_ns` — разность двух `System.nanoTime()`. `1_000_000 ns = 1 ms`. Не путай наносекунды и миллисекунды: CSV хранит ns, таблицы показывают ms.

`max_depth` — самое большое число одновременно вложенных алгоритмических рекурсивных вызовов. Это не число всех вызовов и не количество итераций цикла. Корневой вызов считается первым уровнем. Встроенная сортировка Java в эту метрику глубины не входит.

`recursive_calls` — общее количество входов в рекурсивный метод. `comparisons` — сравнения значений. `swaps` — обмены между разными индексами; обычные присваивания и сдвиги insertion sort не считаются обменами. `distance_evaluations` — сколько раз считалось расстояние.

Есть 4 алгоритма × 4 вида входа × 4 размера × 5 измерений = 320 строк. До измеряемых запусков есть три прогрева каждого сценария, но они в CSV не попадают. В таблице время — медиана пяти запусков, глубина — максимум пяти результатов. Отдельный seed делает каждую попытку повторяемой.

Почему копирование вне таймера? Чтобы время подготовки исходного массива не стало временем сортировки. Но буфер, который создаёт сам алгоритм, входит в его стоимость. Для Closest Pair начальная x-сортировка тоже входит.

Почему числа на ноутбуке будут другими? Среда исполнения другая. Малые тесты особенно чувствительны к JIT, фоновой нагрузке и точности таймера. Три прогрева не гарантируют полную стабилизацию JVM. Один график не доказывает асимптотику.

## 7. Тесты

Для сортировок копируем исходный массив, выполняем `Arrays.sort(expected)` и сравниваем с нашим результатом. В Java `Arrays.sort` ничего не возвращает: запись `Arrays.sort(a)[k]` в задании — идея проверки, а не готовый Java-код.

Для selection сортируем копию и сравниваем с `expected[k]`. Есть 500 случайных наборов и проверка нескольких k, а также проверки всех k на коротких массивах.

Для Closest Pair сравниваем расстояние с перебором O(n²) на малых входах. При одинаковом расстоянии допустимо найти другую пару. Из-за дробной арифметики сравнение расстояний использует допуск. На 100000 точках запускается только быстрый алгоритм; такой smoke test проверяет успешное выполнение, но не заменяет полный эталон.

Добавь собственный тест: например, `checkSort(new int[]{5,-1,5,0,-1,2})` в `sortingTests()`. Сначала выпиши ожидаемый результат `[-1,-1,0,2,5,5]`, затем запусти тесты. Это реальная доработка, которую можно отдельно закоммитить.
