# Как закончить Assignment 1 сегодня

## Сначала важное

Сдаётся ссылка на GitHub-репозиторий, а не ZIP/PDF отдельно. Внутри репозитория должны быть код, тесты, результаты CSV, графики, screenshots, README и настоящая история разработки. Основание — страницы 2–4 твоего Assignment 1.

В пакете есть работающая реализация всех четырёх алгоритмов, тесты, 320 реальных измерений, три PNG-графика и README. Код собран с `javac --release 17` и проверен в Linux-среде с JDK 21. Базовые измерения не сделаны на твоём ноутбуке. Windows-скрипт приложен, но в Windows здесь не запускался.

Ещё не сделаны за тебя: личная Reflection, твои screenshots, загрузка в твой GitHub и история твоих реальных изменений. Не отправляй архив вслепую: сначала запусти и проверь.

## Шаг 1. Открой правильную папку

Распакуй архив. Основной проект — вложенная папка `assignment1-divide-and-conquer`. Именно её открывай в редакторе/IDE. В ней одновременно должны быть `src`, `tests`, `README.md`, `pom.xml` и `run.cmd`.

В Проводнике зайди в эту папку, щёлкни адресную строку, введи `powershell` и нажми Enter. Все следующие команды выполняются там.

```powershell
java -version
javac -version
```

Нужен JDK 17 или новее: должны работать **обе** команды. JRE без компилятора недостаточно. При ошибке «javac не распознан» можно использовать JDK, настроенный в твоей IDE, либо добавить его папку `bin` в PATH. Не скачивай библиотеки алгоритмов: они здесь не нужны.

## Шаг 2. Начни настоящую историю Git

Для новой папки, которая ещё не является Git-репозиторием:

```powershell
git init -b main
git add .
git commit -m "init: import assignment baseline for review"
```

Первый коммит честно фиксирует готовую исходную основу. Не создавай искусственно десять «исторических» коммитов, будто писал алгоритмы в разные дни. После этого отдельно фиксируй реальные проверки и доработки. Критерий Git history прямо требует реальный процесс.

Если Git попросит имя/email, настрой их для этого репозитория своим именем и своим GitHub email. Не копируй чужой email.

## Шаг 3. Проверь демонстрацию и тесты

```powershell
.\run.cmd demo
.\run.cmd test
```

Первый запуск показывает маленькие примеры, второй запускает проверки. В исходном наборе ожидается финальная строка `ALL TESTS PASSED | checks=6593`. После добавления своих тестов число проверок изменится — это нормально.

Посмотри `Main.java`. Убедись, что понимаешь `k=3`: это четвёртое наименьшее число, потому что индекс с нуля.

## Шаг 4. Сделай одну небольшую самостоятельную доработку

Открой `tests/AllTests.java`. Внутри `sortingTests()` добавь проверку массива, который сам можешь отсортировать, например:

```java
checkSort(new int[]{5,-1,5,0,-1,2});
```

Ожидаемый порядок: `[-1,-1,0,2,5,5]`. Запусти `.\run.cmd test` и убедись, что проверка прошла. Затем:

```powershell
git add tests/AllTests.java results/test-output.txt
git commit -m "test: add mixed negative and duplicate values"
```

Это пример полезного настоящего изменения, а не обязательный дополнительный пункт задания.

## Шаг 5. Пересоздай замеры и графики у себя

```powershell
.\run.cmd experiments
```

Обновятся `results/results.csv`, `results/environment.md`, `results/summary.md`, три файла в `docs/plots`, таблицы README и лог экспериментов. Не редактируй цифры вручную. Графики создаёт Java — Python/Excel не нужны.

```powershell
git add results docs/plots README.md
git commit -m "results: record local experiments and plots"
```

`run.cmd all` тоже допустим: он последовательно выполняет тесты, демонстрацию и эксперименты. Прогонять всё заново при каждом чтении файла не нужно.

## Шаг 6. Сделай screenshots и Reflection

Выполни `demo` и `test` отдельно, чтобы удобно было снять окно. `Win+Shift+S` открывает выделение для снимка. Сохрани три картинки в `docs/screenshots`:

- `program-output.png` — понятный вывод demo.
- `test-results.png` — успешный запуск тестов.
- `plots-results.png` — открытый читаемый график или таблица результатов.

Открой README, раздел F. Удали `<!--` и `-->` только вокруг трёх строк изображений, когда файлы действительно добавлены. Не удаляй маркеры `RESULTS_START`/`RESULTS_END`: программа использует их для обновления таблиц.

В разделе E напиши 1–2 абзаца по-английски о том, что лично понял, какую реальную сложность разобрал и как проверил. Не оставляй инструкцию-шаблон как будто это готовая Reflection. Например, после собственного теста можно описать проверку повторяющихся отрицательных чисел; после чтения QuickSort — объяснить отличие цикла от нового рекурсивного вызова. Выбирай только то, что действительно сделал.

```powershell
git add docs/screenshots README.md
git commit -m "docs: add local screenshots and personal reflection"
```

## Шаг 7. Отправь в GitHub

Создай новый репозиторий `assignment1-divide-and-conquer`. Не добавляй README/gitignore/license через сайт — локально они уже есть. Выбери доступ, при котором преподаватель сможет открыть репозиторий; если он приватный, одного URL без предоставления доступа недостаточно.

Скопируй HTTPS URL нового репозитория. Вместо `YOUR_USERNAME` ниже подставь свой GitHub username:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/assignment1-divide-and-conquer.git
git push -u origin main
```

Если GitHub запросит авторизацию, пройди её через открывшееся окно. Не вводи и не публикуй токен в коде или README.

После завершения всех пунктов убери из начала README предупреждение `Working draft`; до этого оно честно обозначает незавершённые личные разделы. Проверь, что описание среды соответствует `results/environment.md`.

Проверь репозиторий через браузер: видны ли исходники, актуальные таблицы, графики и картинки? Открой историю коммитов. Сдай ссылку на репозиторий, не на ZIP.

## План времени — ориентир, не гарантия

20–40 минут: настроить запуск и пройти demo/test. 40–60 минут: разобраться в четырёх основных классах с `docs/DEFENCE_RU.md`. 20–30 минут: своё изменение и местные эксперименты. 30–40 минут: screenshots, Reflection, GitHub и последняя проверка. Проблемы с JDK или Git могут добавить время.

При очень близком дедлайне сначала обеспечь рабочий запуск, полный набор результатов и доступную ссылку, а затем используй оставшееся время для понимания кода. Не рассчитывай на полный балл автоматически: оценку выставляет преподаватель, а история Git и личная часть всё ещё зависят от твоей работы.

## Финальная проверка

Все четыре алгоритма работают. Тесты проходят. В CSV 320 измерений. Три графика открываются. README содержит анализ, результаты и обсуждение. Reflection написана тобой. Три screenshots добавлены и отображаются. История Git фиксирует реальные изменения. Преподаватель имеет доступ к ссылке.
